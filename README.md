# bizhub 185 · macOS 本机打印驱动

当前 Mac 已安装 **0.3.5**。系统队列为 `bizhub185`，显示名称为 **KONICA MINOLTA bizhub 185**，是当前用户默认打印机。

已验证 USB 实机出纸、纵向与横向打印、文字 B 和灰度 D。原尺寸校准页的 100 mm 横线经用户实测为 10 cm。右侧仍约有 2 mm 留白；贴近纸边的内容不能保证原位完整输出。本驱动不承诺无边框打印。

## 使用

在应用中按 ⌘P，选择 **KONICA MINOLTA bizhub 185**，纸张选 **A4**，方向可选纵向或横向。保持原尺寸/100%/不缩放，不启用“适合纸张”。

- 默认 **Auto (Text or Photo)** 逐页选择文字、自然灰阶或彩色细节模式。
- **Text (B - Stronger)** 用于文字和线条，阈值为 160。
- **Photo (Color Detail)** 将部分色差转成灰度差，帮助区分亮度接近的颜色。
- **Photo (Brighter Gray)** 用于灰阶图片。0.3.3 在误差扩散前使用树林对照页第 3 栏的暗部曲线，中灰和亮部沿用 C 曲线（gamma 0.62），保留纯黑和纯白。
- **Photo (Natural Gray)** 使用人像试印 A 档。相较于 Brighter Gray，中灰更深，暗部带有轻度纹理增强。
- A4、600 dpi、黑白、单面；接受纵向、横向以及带 `/Rotate` 90°/270° 的 A4 PDF。
- 软件检查覆盖 1–100 页、1–99 份及异常输入拒绝；多页和多份尚未做实机专项测试。
- 其他纸型和双面设置会报错。

在 **Printer Options → Printer Features → ⓘ → Black and White Rendering** 可手动选档。WPS 会缓存打印选项。升级后若仍显示旧列表，请保存文档，用 ⌘Q 退出 WPS，再打开文档和打印窗口。

## 原尺寸与纸边限制

0.3.0 的 PPD 曾向应用声明四周约 4 mm 的可打印矩形，WPS 即使未勾选“适合纸张”，也会据此把内容内缩。0.3.1 改用完整 A4 逻辑版面 `ImageableArea [0 0 595.2756 841.8898]`，并设置队列默认不缩放。过滤器及文字 B、灰度 D 算法保持不变。

同一份文档的右侧墨迹，在 WPS 生成的打印页面中由旧版约 4.32 mm 恢复为约 0.35 mm；驱动编码再解码后约为 0.30 mm。标准 A4 校准横线的栅格长度为 100.034 mm，符合 600 dpi 像素取整，纸面实测为 10 cm。

该文档本身宽 210.1003 mm，略大于标准 A4。WPS 仍会作约 0.048% 的纸型归一化：页眉线从 146.5086 mm 变为 146.4386 mm，旧版则为 140.8604 mm。取消额外内缩不等于所有非标准纸型都数学上完全 1:1。

实机右侧仍约有 2 mm 留白。曾单独测试扩大栅格并右移 1.524 mm：标尺仍为 10 cm，左侧改善，但右侧 0.5/1 mm 标记消失，2 mm 标记可见。该实验会损失靠边内容，未安装到系统。

定位测试结束后沿用 0.3.1 的纸边方案。定位测试 B 的脚本、打印数据及预览图已移除；诊断 JSON、用户反馈和基线照片保留在 W 盘 `registration-test-B`。不再自动重印或继续该实验。

官方《User’s Guide》1.2.0 的 PDF 第 134 页（印刷页码 12-4），机身规格列出四周 4 mm 的 `Image chipping width`。这是标称机身规格，不是本次 USB 打印右边界的精确测量值。官方手册及下载校验信息保存在 W 盘 `official-manual`。严格贴边且保留全部内容的输出尚未实现；更大纸张打印后裁切可作为后续方案，当前驱动尚未支持和验证。

## 开发与复现

```sh
cd /Users/michael/Documents/ChatGPT/printer
make all
make build/pbm-jbig build/bizhub185-filter
make test
make test-native
python3 tools/build_installer.py
```

JBIG 源码位于 W 盘 `jbigkit-source`；`JBIG_SOURCE` 可覆盖其构建位置，默认路径先检查 W 盘身份。原生协议对照检查还需要 `build/vendor` 中的 Unicorn 和已下载的官方模块。安装后的过滤器没有这些运行时依赖。

`gdi.py` 和 `xps_test.py` 保留早期纵向编码和 XPS 研发入口；直接发送 XPS 的早期测试没有出纸，因此正式驱动采用已验证的 PJL/JBIG 通路。`tools/protocol_oracle.py` 仅模拟官方模块的局部函数，不是完整 Windows 环境。构建、编码和离线检查不会自动发送实机任务；带发送参数的早期工具使用独占记录防止重复投递。

原生程序链接 GPL JBIG-KIT，相关源码和许可一起打包。官方 Windows 模块不打包或分发，详见 `THIRD_PARTY.md`。
